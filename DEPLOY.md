# Deploy guide — GitHub Pages + Render (Docker)

This app is a monorepo:

- `apps/web` → static SPA on **GitHub Pages**
- `apps/server` → NestJS API on **Render** (Docker)
- MongoDB Atlas → database
- Cloudinary → project image storage

Docker is used for the API so Render can **restart the container automatically** if the process crashes. A Docker `HEALTHCHECK` plus Render’s `healthCheckPath` (`/rest/health`) keep the service monitored.

---

## 1. Prerequisites

1. MongoDB Atlas cluster + connection string (`DATABASE_URL`)
2. Cloudinary account (cloud name, API key, API secret)
3. GitHub repo with Actions + Pages enabled
4. Render account

---

## 2. Deploy the API on Render (Docker)

### Option A — Blueprint (recommended)

1. Push this repo (includes `render.yaml` + `apps/server/Dockerfile`).
2. In Render: **New → Blueprint** → select the repo.
3. Render creates `veershree-api` as a **Docker** web service.
4. Fill env vars marked “sync: false” in the dashboard:

| Variable | Example |
|----------|---------|
| `DATABASE_URL` | `mongodb+srv://...` |
| `CORS_ORIGIN` | `https://<user>.github.io` (comma-separate multiple origins) |
| `ADMIN_SEED_PASSWORD` | strong password for seeded admins |
| `CLOUDINARY_CLOUD_NAME` | from Cloudinary dashboard |
| `CLOUDINARY_API_KEY` | from Cloudinary dashboard |
| `CLOUDINARY_API_SECRET` | from Cloudinary dashboard |
| `SMTP_*` | optional email settings |

`JWT_SECRET` is auto-generated by the blueprint. `CLOUDINARY_FOLDER` defaults to `veershree`.

5. After deploy, open:

`https://<your-service>.onrender.com/rest/health`

You should see `OK`.

### Option B — Manual Docker service

1. **New → Web Service** → connect repo.
2. Runtime: **Docker**
3. Dockerfile path: `apps/server/Dockerfile`
4. Docker build context: repo root (`.`)
5. Health check path: `/rest/health`
6. Set the same env vars as above, plus:

```env
NODE_ENV=production
PORT=3000
```

### Auto-restart behavior

- If Node exits (uncaught error, OOM, etc.), **Render restarts the Docker service**.
- The image `HEALTHCHECK` probes `/rest/health` every 30s.
- Render also uses `healthCheckPath: /rest/health` for routing/health.

No extra process manager (PM2) is required on Render when using Docker.

### Local Docker smoke test

```bash
# From repo root — uses apps/server/.env
docker compose up --build
curl http://localhost:3000/rest/health
```

`restart: unless-stopped` in `docker-compose.yml` restarts the container on crash locally.

## 3. Point the frontend at the API

In GitHub → **Settings → Secrets and variables → Actions**:

| Secret | Value |
|--------|-------|
| `VITE_SERVER_URL` | `https://<your-service>.onrender.com` (no trailing slash) |
| `VITE_SITE_URL` | Public site origin, e.g. `https://veershreerealty.com` or your GitHub Pages URL |

Optional repo **variable**:

| Variable | Value |
|----------|-------|
| `VITE_BASE` | `/` if using a custom domain at site root; otherwise omit (defaults to `/<repo>/`) |

---

## 4. Deploy the web app to GitHub Pages

1. **Settings → Pages → Source**: GitHub Actions.
2. Merge/push to `main` (or run **Deploy web to GitHub Pages** manually).
3. Workflow builds with `VITE_BASE` + `VITE_SERVER_URL`, uploads `apps/web/dist`, and deploys.

Site URL (project pages):

`https://<user>.github.io/<repo>/`

### CORS

On Render, set `CORS_ORIGIN` to your Pages origin, for example:

```text
https://<user>.github.io
```

If you also develop locally against the deployed API:

```text
https://<user>.github.io,http://localhost:5173
```

## 7. SEO after go-live

1. Confirm these URLs return **200** (not 404):
   - `https://veershreerealty.com/favicon.ico`
   - `https://veershreerealty.com/favicon-48x48.png`
   - `https://veershreerealty.com/robots.txt`
   - `https://veershreerealty.com/sitemap.xml`
2. In [Google Search Console](https://search.google.com/search-console):
   - Submit / refresh the sitemap
   - Use **URL Inspection → Request indexing** for `/`, `/projects`, `/why-land`, `/contact`
   - Under **Branding → Favicon** (or wait for recrawl), confirm the 48×48 PNG is detected
3. Create a Business Profile for **Veershree Realty** (maps/local brand searches).
4. Prefer a custom domain (`veershreerealty.com`) over a long GitHub Pages URL for brand queries.

**Favicon note:** Google Search ignores SVG-only favicons. This app ships `favicon.ico` + `favicon-48x48.png` (required). After deploy, favicon updates can take **days to weeks**.

**Sitelinks note:** Links like Projects / Why Land / Contact under the main result are chosen by Google. We expose them via clear nav, sitemap, clean page titles, and `SiteNavigationElement` schema — they are not guaranteed and usually appear after enough traffic/crawling.

Technical SEO is wired in the web app (titles, canonicals, Open Graph, JSON-LD, sitemap). Ranking and sitelinks still depend on Search Console verification, consistent NAP (name/address/phone), and links from directories/social.
